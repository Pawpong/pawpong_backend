# 운영 DB 백업 및 환경 변수 관리

상태: 백업 API·워커·관리자 UI 구현 및 로컬 빌드/단위 테스트 완료. Control 전용 키 설정 전 운영 백업과 스케줄은 비활성 상태이며, 실제 S3 백업 및 격리 DB 복원은 아직 검증하지 않음.

## 확정 범위

- MongoDB `prod`만 백업한다. `dev` 및 다른 데이터베이스는 대상이 아니다.
- Pawpong 관리자에서 수동 실행 및 실행 이력을 제공한다.
- 자동 실행과 수동 실행은 같은 비동기 작업 경로를 사용한다.
- 운영 사용자 데이터는 읽기만 하며 복원·삭제 API는 이번 범위에 포함하지 않는다.
- 운영 환경 변수 변경은 Control의 `pawpong-production` 대상과 암호화 백업·버전 충돌 검증 경로만 사용한다.
- 로컬 `.env`에 운영 키를 복제하지 않는다. 개발 실행과 테스트는 개발 DB 또는 격리 DB만 사용한다.

## 운영 적용 전 확인 사항

- 백업 전용 비공개 SmileServ S3 버킷 및 최소 권한 서비스 자격 증명.
- 별도로 보관할 암호화 키와 키 버전. 복호화 키를 백업 객체/manifest와 함께 저장하지 않는다.
- Control 인증 및 해당 대상의 읽기·쓰기·배포 권한.
- 자동 실행 제안: 매일 03:00 Asia/Seoul. 보관 기간 제안: 30일. 운영자 확정 전 자동 삭제/스케줄은 비활성화한다.

## 구현 경계

- 관리자 API는 super_admin 등 명시적인 백업 권한을 검증한다. 일반 통계 조회 권한으로 덤프를 가져갈 수 없도록 한다.
- POST 실행은 202와 작업 ID를 반환하고 HTTP 요청에서 덤프를 기다리지 않는다.
- 요청에서 URI, DB명, 버킷, 경로, 셸 옵션을 받지 않는다. 서버 설정에서만 읽으며 DB명은 `prod`로 고정한다.
- 분산 잠금으로 blue/green 컨테이너 및 수동/정기 실행의 중복을 차단한다. 만료 갱신과 장애 복구를 제공한다.
- 전용 워커에 CPU/메모리/디스크 상한, 타임아웃, 단일 컬렉션 병렬도 제한을 둔다.
- mongodump 자격 증명은 프로세스 인자나 로그에 넣지 않는다. 압축 결과는 인증 암호화한 뒤 업로드한다.
- 기존 StorageService는 public-read 업로드를 사용하므로 재사용하지 않는다. 공개 CDN 경로·일반 파일 보관함에도 노출하지 않는다.
- 객체 접근 차단과 업로드 길이/체크섬을 확인한 뒤에만 succeeded 처리한다. 실패 시 부분 업로드와 작업 소유 임시 파일만 정리한다.
- 이력에는 실행자, manual/scheduled, 시작/종료 시간, 상태, 암호화 파일 크기, checksum, 키 버전, 정제된 오류 코드만 기록한다.
- 보관 기간 정리는 전용 prefix의 완료된 백업만 대상으로 한다. 일반 이미지나 현재 진행 작업은 삭제하지 않는다.
- 복원 검증은 운영 DB가 아닌 격리 MongoDB에서 수행한다. 단순 업로드 성공을 복원 가능성 검증으로 표현하지 않는다.

## 일관성 제한

`mongodump --db=prod` 논리 백업은 동시 쓰기가 있는 동안 컬렉션 간 동일 시점을 보장하지 않는다. UI와 manifest에 이 한계를 표시한다. 다른 DB까지 읽는 전체 덤프를 임의로 수행하지 않는다. 시점 복원이 필요하면 별도 스냅샷 정책을 결정한다.

참고: https://www.mongodb.com/docs/database-tools/mongodump/

## 발견된 환경 관리 충돌

- Nest 로컬 실행: src/app.module-definition.ts의 `.env` 로딩.
- Docker 운영 실행: docker-compose.yml의 `.env.production` 주입.
- prod-deploy.yml의 Configure AI Agent credential 단계를 제거하고 운영 환경 파일 존재 여부만 읽는 검사로 대체했다. Control에서 관리하는 운영 키를 CI가 덮어쓰지 않는다.
- Control의 환경 파일 백업과 이번 MongoDB 데이터 백업은 별도 기능이다. 한쪽의 성공으로 다른 쪽의 백업 완료를 판단하지 않는다.

## 필수 검증

- prod 이외 URI 거부, 권한 없는 수동 실행 거부, 중복 요청 차단.
- 덤프 실패/업로드 실패/타임아웃/재시작 후 상태 복구.
- 비밀값 로그 미노출, 공개 객체 접근 거부, 암호문 변조 감지.
- 완료 이력 및 관리자 오류/재시도 UI, 보관 정책 대상 경계.
- 암호화 백업을 격리 DB에 복원하고 컬렉션·인덱스 및 표본 레코드 확인.
